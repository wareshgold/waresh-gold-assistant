# Waresh Gold Assistant — Website v2 Project Snapshot

Date: 2026-09-02
Branch: `feature/website-v2`
Repository: `wareshgold/waresh-gold-assistant`

## Purpose

Waresh Gold is being evolved from a Telegram-first bot into a reusable Gold Business Platform for the Iranian gold and jewelry market. Telegram is only one interface. The long-term platform can power the website, mobile apps, REST API, CRM, admin dashboard, AI assistants, and business automation.

## Architecture Principles

- Clean Architecture
- Domain-Driven Design principles
- SOLID
- TypeScript-first
- Modular and testable design
- Business logic independent of Telegram, HTTP, databases, Cloudflare, and AI providers
- AI orchestrates tools but does not implement trusted gold calculations
- Financial calculations belong to domain/application services

## Current Website Architecture

The website is now source-controlled inside the main repository instead of relying on manually uploaded static Cloudflare files.

Expected public information architecture:

```text
wareshgold.ir/
├── /          Store / sales homepage
├── /about     Waresh story and brand narrative
└── /tools     Gold tools
```

The important routing decision is that `/about` and `/tools` are siblings. About is NOT a child of Tools.

## Calculator / API Boundary

The frontend does not implement trusted gold pricing formulas itself.

`dashboard/src/app/api/calc/route.ts` proxies calculator requests to the core API.

The architecture remains:

```text
Website
  ↓
API adapter
  ↓
Core gold calculation service
  ↓
Verified result
```

## Current UX Status Before Scroll v1

The website pages render correctly locally at:

```text
http://localhost:3000/
http://localhost:3000/about
http://localhost:3000/tools
```

The major remaining UX gap is scroll experience.

Current page behavior is primarily normal section stacking. The desired experience is an editorial, premium scroll narrative inspired by the interaction logic of high-end studio sites, without copying another site's visual identity.

Desired characteristics:

- sections reveal as scenes
- subtle parallax
- sticky focal elements where useful
- controlled image scale/position movement
- staggered text entrance
- generous whitespace
- organic rather than card-heavy composition
- no scroll hijacking
- graceful reduced-motion behavior
- natural atmospheric rain rather than repetitive falling-line effects

## Known Existing UX Caveat

The homepage currently has a mobile hamburger-looking control, but it is only a styled anchor and is not yet a real mobile menu/drawer. This should be addressed during the navigation/UX pass.
